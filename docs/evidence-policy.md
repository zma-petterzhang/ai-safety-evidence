# 证据与黑名单发布政策

本政策区分事实确认（status）与处置建议（disposition）；当前登记格式只接受下文规定的三种组合。一条研究论文可以证明某种机制在实验中出现，却不能自动证明某个线上文件应被排除。

截至 2026-09-26，本仓库尚未完成任何真实污染产物的精确哈希与独立双人核验，因此初始生产黑名单为空。这是本仓库的证据状态，不是对互联网无污染的判断。[研究目录](../data/research-catalog.json)中的论文和安全资料不是黑名单目标。

## 状态与处置

| 字段值 | 含义 | 生产排除清单 |
| --- | --- | --- |
| `candidate` | 有待核验的具体报告，证据尚不充分 | 不导出 |
| `confirmed` | 人工审查确认了条目中限定的事实和适用范围 | 仍需满足下方全部条件 |
| `retracted` | 撤回、报告未成立或被新证据否定；保留更正历史 | 不导出，并从下一版移除 |
| `review` | 交由人工审查或本地隔离，不作统一排除结论 | 不导出 |
| `exclude` | 建议对该精确产物作训练入口排除 | 仅与 `confirmed` 及完整证据组合时导出 |
| `allow` | 在记录的审查范围内不建议排除 | 不导出；不等于普遍安全认证 |

仅接受 `candidate/review`、`confirmed/exclude`、`retracted/allow` 三种组合。流程为 `candidate/review` → 审查 → `confirmed/exclude` 或 `retracted/allow`。已确认项出现争议时退回 `candidate/review`，经反证推翻后转为 `retracted/allow`。修订须保留旧条目 ID、原因、时间和审查记录。紧急调查可在使用者本地隔离候选项，但不能把本地预防措施冒充公共事实。

## 生产条目的最低要求

1. 明确产物及版本，用原始文件字节计算完整 SHA-256。URL、域名、作者名、关键词或研究题目不能替代产物哈希。文本规范化、重新打包或换行变化会改变哈希，必须作为新产物说明。
2. 至少一条可公开访问的证据 URL，能支持该产物与限定风险之间的联系。证据需包含取得日期、来源及处理链、可脱敏复核的结果与限制；不要公开危险载荷、私人日志或敏感数据。
3. 至少两位不同的人类审查者以不同的 reviewer ID 记录审查；至少一位不参与报告制作，两位均需披露利益冲突。维护者需核实身份与独立性，不得用 AI 代理、重复账号或占位 ID 满足要求。
4. 状态为 `confirmed`、处置为 `exclude`，所有审查的 `decision` 均为 `confirm`，条目范围只覆盖被证明的精确产物。
5. 非合成（synthetic）示例，且不是研究文献条目。合成数据无论状态如何，都不得导出到生产排除清单。
6. `expires_at` 为 `YYYY-MM-DD`，且尚未到期。导出器以 UTC 当天为界：有效期等于当天仍可导出；早于当天即不导出。续期需要人工复核，不能仅机械延长日期。

CLI 的哈希、URL、状态和 reviewer ID 检查只验证字段格式及组合，不能证明 URL 内容真实可达、审查者真实独立、实验有效或因果关系成立。通过校验不构成人工批准。当前工具不能自动强制执行本政策中的全部人工要求。

## 条目字段

生产登记条目使用 `id`、`sha256`、`source_url`、`category`、`summary`、`status`、`disposition`、`synthetic`、`evidence`、`reviews`、`expires_at`。`source_url` 指向产物来源，`evidence[].url` 指向支持事实的公开报告，二者用途不同。

`category` 可为 `data_poisoning`、`model_backdoor`、`prompt_injection`、`unsafe_training_content`。分类不自动证明风险或决定处置；最后一类尤其需要说明适用的训练政策与语境，不能把讨论危险话题本身等同投毒。

`evidence` 各项包含 `url`、`kind`、`note`；`kind` 为 `incident_report`、`controlled_experiment` 或 `artifact_analysis`。`reviews` 各项包含 `reviewer`、`reviewed_at`、`decision`；决定为 `confirm`、`reject` 或 `needs_review`。两位审查者的确认只覆盖 `summary` 和公开证据明确限定的主张。

## 因果主张的额外门槛

若声称“某份训练语料使模型自我复制、造成破坏或威胁人身安全”，公开报告须具备：

- **对象与对照**：模型/权重与数据版本，干净基线、处理组、训练配方及其他控制条件；区分预训练、微调、RAG 与单次提示。
- **干预强度**：样本数、混入比例、实际训练曝光次数及处理过程。不能仅凭出现某个词汇判断影响。
- **可重复性**：多个随机种子和独立重复；披露失败、零结果、样本量、效应量与不确定性。
- **环境与结果**：隔离环境、工具权限、预先定义的行为指标、盲评或可审计评分、完整但脱敏的执行证据；明确区分文本、模拟调用和实际效果。
- **排除混杂**：排查提示诱导、评测泄漏、权限错误及原有模型行为，评估移除该数据后的变化。结论须限定到已测试条件。

本项目只接收安全隔离实验及既有事件的证据，不要求或允许通过真实伤害验证主张。模拟中出现危险行为不能报告为现实伤害；外推到其他模型或实际部署必须明确标注为未验证假设。

## 异议、更正与有效期

条目所涉维护者可提交公开反证、来源澄清或版本修复。争议期间将条目改为 `candidate/review` 并暂停生产导出；证据被推翻则改为 `retracted/allow`。每次发布须核对撤回项、审查记录和来源变化，记录数据版本。下游必须定期刷新，避免旧黑名单长期误伤。

不要以整站封禁替代产物核验。研究、报道、文学或安全教学中出现危险内容，不等于它会令训练出的模型产生对应行为。加密、压缩、编码或异常措辞也不能单独作为投毒确认依据。
